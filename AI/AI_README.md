# AI 개발 계획

[통합 개발 계획](../docs/development-plan.md) · [BE1 개발 계획](../docs/roles/BE1_README.md) · [BE2 개발 계획](../docs/roles/BE2_README.md)

**담당은 BE1·AI 담당자**, 구현 언어는 **Python**이다. 첫 모델 후보는 **Solar Mini 4**이며 합성 입력의 품질·응답 시간 평가 후 확정한다.

## Spring 백엔드와의 연결 제안

- Spring의 작업 처리기가 Python 내부 HTTP API에 요청 ID, 처리 시도 식별자, 분석에 필요한 입력을 보낸다. 브라우저는 Spring API로 상태를 조회한다. Python 내부 API의 접근 방식은 배포 환경에 맞춰 정한다.
- Python이 위기 분기와 Solar 호출·응답 검증을 처리한다. 정상 분석·위기 안내·실패를 구분해서 반환하며 요청 본문, 모델 응답, API 키를 로그에 남기지 않는다.
- Spring이 작업 제한 시간과 재시도, PostgreSQL 저장, 삭제·만료 검사를 관리한다. Python은 제공자 호출에 제한 시간을 두고 결과를 반환한다. AI 구현과 테스트는 PostgreSQL 연결 없이 진행한다.

## Python 테스트 서버 실행

Windows PowerShell에서 저장소 루트로 이동한 뒤 실행한다.

```powershell
python -m venv .\AI\.venv
.\AI\.venv\Scripts\python.exe -m pip install -r .\AI\requirements.txt
.\AI\.venv\Scripts\python.exe -m uvicorn mock_api:app --app-dir AI --host 127.0.0.1 --port 8001 --no-access-log
```

Spring의 루트 `.env`에 `NIGHTVAULT_AI_URL=http://127.0.0.1:8001/internal/v1/analyze`를 추가하고 `local` 프로필로 Spring을 시작한다. 선택적으로 내부 Bearer 인증을 테스트하려면 Python을 시작하는 PowerShell과 Spring의 `.env`에 동일한 `NIGHTVAULT_AI_TOKEN`을 설정한다.

일반 입력은 고정된 성공 콘텐츠를 반환한다. `[mock:guidance]`는 S-16 도움 안내, `[mock:failure]`는 최종 실패, `[mock:timeout]`은 Spring의 로컬 작업 제한 시간 3초를 넘기는 응답을 만든다. 연결 실패와 시간 초과는 기존 작업 큐에서 최초 시도를 포함해 최대 3번 처리한다. 이 서버는 합성 입력으로 내부 HTTP 계약을 확인하는 용도다.

## Solar 연동 확인

저장소 루트의 `.env`에 발급한 `UPSTAGE_API_KEY`를 설정한 뒤 아래 값을 추가한다. 앞의 Python 실행 명령으로 의존성을 설치하고 Python과 Spring을 다시 시작한다. Python 설정은 프로세스 환경변수를 우선 읽고, 값이 없으면 저장소 루트의 `.env`를 읽는다.

```dotenv
NIGHTVAULT_AI_MODE=solar
NIGHTVAULT_AI_URL=http://127.0.0.1:8001/internal/v1/analyze
UPSTAGE_MODEL=solar-mini4
UPSTAGE_TIMEOUT_SECONDS=10
NIGHTVAULT_AI_TIMEOUT_SECONDS=12
```

- 합성 걱정을 Spring의 제출 API에 보내고 `requestId`로 조회해 `SUCCEEDED`를 확인한다. Python은 걱정 원문만 Solar에 전달하고, 요약·추천·액션 3단계·휴식·공감의 응답 계약을 확인한다. 모델과 연동을 검증하는 로컬 모드이며 실제 위기 대응 연결은 별도 정책에 따른다.
- Spring 작업 제한은 Python의 모델 호출 제한보다 길게 설정한다. PostgreSQL 선점 기한은 Spring 작업 제한에 저장 여유 5초를 더한다. 시간 초과·호출 한도·일시 장애는 Spring이 최대 3회 시도하고, 형식 오류와 자격 증명 오류는 최종 실패로 처리한다.
- 테스트 분기는 `NIGHTVAULT_AI_MODE=mock`에서 확인한다. Python까지 호출할 때도 모의 타임아웃을 재현하려면 Spring 작업 제한을 기본 3초로 되돌린다.

## 개발 범위

| 기능 | 책임 |
| --- | --- |
| 입력 계약 | 걱정 원문 최대 500자, 불안도 1~5, 선택 메모 최대 100자라는 제출 계약을 공유한다. 어떤 필드를 실제 모델에 보낼지는 기능상 필요성과 데이터 처리 조건에 따라 정한다. |
| 위기 대응 | 일반 생성 전에 별도 정책에 따른 규칙과 맥락을 확인한다. 규칙상 명확한 신호는 LLM 실패 시에도 도움 안내로 분기한다. 전체 판단 실패는 오류로 반환한다. |
| 구조화 생성 | 요약, 추천 도움 유형 1개와 이유, 액션 정확히 3단계, 휴식 안내, 짧은 공감 메시지를 생성한다. 사용자 입력은 분석할 데이터로 전달한다. |
| 검증·오류 | 필수 필드, 자료형, 추천 유형, 단계 수와 빈 문장을 검사한다. API 타임아웃·요청 제한·형식 위반 등 오류는 BE1이 처리할 수 있는 코드로 전달한다. |
| 운영 경계 | API 키는 서버 비밀 설정으로 관리한다. 합성 입력으로 평가하고 실제 원문과 모델 응답을 일반 로그에 남기지 않는다. |

## 구현 순서

| 순서 | 작업 | 산출물과 완료 기준 |
| --- | --- | --- |
| 1 | AI 입력·출력·오류 규격 정의 | 정상 분석·위기 안내·실패 예시를 작성한다. 유효한 예시는 통과하고 필수 값 누락, 추천 값 오류, 2단계·4단계 액션은 거부한다. |
| 2 | Python 내부 API와 가짜 응답 구현 | API 키 없이 성공, 위기 안내, 응답 검증 실패, 시간 초과를 재현한다. Spring에서 이 응답을 받아 상태를 올바르게 처리하는 계약 검증을 추가한다. |
| 3 | 한국어 프롬프트와 응답 검증 구현 | 원문에 없는 사실이나 결과를 단정하는 문장, 사용자 입력에 섞인 명령, 진단 표현을 합성 사례로 확인한다. 사용자가 실행할 수 있는 작은 행동을 제시하는지 검토한다. |
| 4 | Solar 구조화 출력 연결 | API가 반환한 JSON을 Python에서 검증하고, Spring은 내부 응답 계약을 확인한 뒤 사용한다. 제공자 호출의 제한 시간은 Python이 적용하고 작업 재시도는 Spring에서 관리한다. |
| 5 | 위기 판단 규격과 정책 연결 | 정상·도움 안내·판단 실패 경로를 별도로 확인한다. 감지 조건과 안내 문구는 별도 위기 대응 정책을 받은 뒤 확정한다. 위기 경로에서는 일반 콘텐츠 생성을 중단한다. |
| 6 | 한국어 품질·응답 시간 평가 | 요약 충실도, 추천 근거, 액션 실행 가능성, 공감 문구, 검증 실패율과 지연을 기록한다. 측정 결과로 모델과 입력·출력 길이 제한을 확정한다. |
| 7 | BE1 연결과 통합 점검 | AI 성공 결과는 BE1이 저장을 완료한 뒤 봉인 상태로 전환한다. 모델 타임아웃·중복 처리·삭제 후 늦은 응답을 통합 테스트한다. |

## BE1·BE2와 공유할 규격

| 반환 결과 | 포함할 정보 | 연결 동작 |
| --- | --- | --- |
| 정상 분석 | 검증된 요약, 추천 유형·이유, 액션 3단계, 휴식 안내, 공감 메시지 | BE1이 걱정과 콘텐츠를 저장하고, BE2는 공개된 콘텐츠로 활동을 연결한다. |
| 위기 안내 | 별도 안내 흐름에 필요한 상태와 정책에서 정의한 정보 | 앱 안에서 S-16 진입을 제공한다. 일반 봉인·기록·예약에서 제외한다. |
| 처리 실패 | 민감한 입력·응답이 없는 오류 유형과 재처리 판단에 필요한 정보 | BE1이 작업 상태·재시도·임시 원문 정리를 관리한다. |

AI 추천과 사용자 선택은 서로 다른 값으로 취급한다. 사용자가 요약을 수정하거나 다른 도움을 선택하면 BE2는 수정본과 선택을 기록하고, 봉인 때 생성한 콘텐츠를 재사용한다.
