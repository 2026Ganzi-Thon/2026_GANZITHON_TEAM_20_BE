# BE2 개발 계획

[통합 개발 계획](../development-plan.md) · [AI 개발 계획](../../AI/AI_README.md) · [BE1 개발 계획](BE1_README.md)

공개된 걱정을 확인한 뒤 사용자가 고른 도움과 그 결과를 기록한다. 활동·평가, 기록·회고·과거 경험, 파쇄와 공통 삭제·만료, 권한이 있는 시연 흐름을 담당한다.

## 담당과 스택

**BE2 담당자**가 Java 21, Spring Boot 4.1.x, Spring Security, PostgreSQL로 구현한다. BE1과 하나의 Spring 백엔드, 공통 인증·인가와 PostgreSQL 마이그레이션을 공유하고 기능별 패키지에서 작업하는 구성을 제안한다.

## BE1과 먼저 맞출 데이터 계약

- **걱정과 AI 콘텐츠**의 ID와 공개 상세 응답을 먼저 합의한다. BE2는 이 계약의 가짜 데이터로 활동·평가 개발을 시작하고, 봉인과 공개가 연결되면 통합한다.
- **활동과 기록**은 걱정별 이력을 보존한다. 완료 상태와 평가를 따로 저장하고, 완료와 중단이 동시에 요청되거나 같은 활동 시작이 재전송되는 경우에 적용할 상태 전이와 유일 제약을 정한다.
- **삭제와 만료**는 BE2가 공통 흐름을 구현한다. BE1은 동일한 삭제 상태를 확인해 분석 성공 저장과 예약 발송을 차단한다. 분석 완료와 전체 삭제가 겹치는 경우를 PostgreSQL 통합 테스트로 재현한다.
- **시간 기준**은 서버에서 공유한다. 회고의 24시간은 실제 공개 가능 시각으로 계산하고, 오늘 건너뛰기는 사용자 현지 날짜로 판단한다. 홈 이어하기에 필요한 진행 상태는 BE1과 계약을 맞춘다.

## 구현 순서

| 순서 | 범위 | 구현할 내용 | 완료 기준 |
| --- | --- | --- | --- |
| 0 | 공동 ERD·API 검토 | 걱정·활동·평가·회고의 관계와 FK, 삭제 시 함께 정리할 데이터를 정리한다. 공개 상세와 활동 상태 예시를 합의한다. | BE1의 봉인 작업과 병행해 합의된 예시로 기록·활동 API를 구현할 수 있다. |
| 1 | 공개 기록·상세 | BE1의 인증·소유권·공개·삭제·만료 검사를 공통 사용한다. 공개 기록 목록·상세, 최초 상세 열람, 수정 요약 우선 표시, 현재 불안도 선택·수정을 구현한다. | 기록 목록에는 공개·유효한 항목만 최신순으로 표시된다. 요약 수정은 원문과 생성 콘텐츠를 유지하고, 전후 불안도가 모두 있을 때만 변화량을 제공한다. |
| 2 | 활동과 선택 | 추천과 별개로 도움 4종을 선택할 수 있게 한다. 진행·일시정지 중 도움을 변경하면 확인 후 기존 활동을 중단하고 새 도움으로 전환한다. 액션 체크와 활동 이력을 보존한다. | 변경 취소 시 기존 상태가 유지된다. 같은 활동을 다시 열어도 활동이 중복 생성되지 않고 홈·기록에서 이어하기 정보가 일치한다. |
| 3 | 액션·휴식·공감 | 액션은 진입 시 시작하고 3단계 체크를 저장한다. 휴식은 사용자 시작 후 3분 타이머를 실행하며 서버 상태로 일시정지·재개를 복원한다. 공감은 봉인 때 생성한 메시지를 표시한다. | 액션은 3단계 체크 뒤 완료할 수 있다. 휴식 0초와 공감 조회는 각각 완료 버튼·읽었어요 확인 전까지 완료로 기록되지 않는다. 휴식을 그만둔 뒤 다시 시작하면 3분이다. |
| 4 | 완료·평가 | 액션·휴식·공감의 명시적 완료를 저장하고, 도움 여부를 선택 입력으로 기록한다. 공개된 다른 미확인 걱정이 있을 때 다음 걱정 선택을 제공한다. | 활동 완료와 평가 저장 실패가 구분된다. 평가 없이 이동해도 완료 상태가 유지된다. 파쇄는 삭제 흐름으로 종료된다. |
| 5 | 회고·과거 경험 | 최초 공개 가능 시각부터 24시간이 지났고 상세 열람한 미응답 기록 중 가장 오래된 유효 후보 하나를 고른다. 현지 날짜 기준 오늘 건너뛰기를 처리한다. 관련 과거 경험은 같은 게스트의 공개·유효 기록에서 최대 하나를 고른다. | 현재 확인 중인 기록은 회고·과거 경험 후보에서 빠진다. 관련성이 부족하면 카드를 숨기고, 도움 됨 평가가 있는 경험만 도움이 됐다고 표시한다. |
| 6 | 파쇄·삭제·만료 | 파쇄·일반 삭제·만료가 공통 삭제 처리를 사용하도록 한다. 조회를 먼저 차단하고 원문·AI 결과·수정본·활동·평가·회고·검색·캐시·연결 예약을 정리한다. 전체 삭제는 진행 중인 요청과 게스트 설정까지 BE1과 처리한다. | 접수 30일이 지나면 정리 작업 완료 전에도 접근이 차단된다. 부분 실패 후 재처리할 수 있고 반복 삭제는 완료 상태로 처리된다. 늦은 AI 응답으로 기록이 되살아나지 않는다. |
| 7 | 시연·통합 점검 | S-18에 서버 권한 검사를 적용하고 시연 기록·타임머신·장애 프리셋·초기화를 구현한다. 운영 데이터와 실제 알림을 분리한다. | 일반 이용에서는 시연 패널에 접근할 수 없다. 타임머신·초기화가 운영 기록을 바꾸지 않고 실제 알림이나 전화 연결을 실행하지 않는다. |

## 상태와 시각 처리

- 활동 상태는 시작 전·진행 중·일시정지·중단·완료를 구분한다. 실행 중 화면 이탈 시 휴식 타이머는 계속 흐르고, 일시정지 상태는 남은 시간을 유지한다. 액션 중단 후에는 이전 체크로 재개한다.
- 회고의 최초 공개 가능 시각은 저장 성공과 공개 시각 조건을 모두 충족한 시점이다. 예정 공개 시각보다 늦게 저장됐다면 저장 성공 시각부터 24시간을 계산한다.
- 과거 경험은 조회 직전에도 소유권·공개·삭제·만료를 검사한다. 검색에 파생 데이터를 쓰는 경우 원본 삭제·만료 때 함께 제거한다. 관련성 판단 방식과 임계 기준은 구현 전에 정한다.
- 삭제 결과가 확정된 뒤에 파쇄·삭제 완료를 반환한다. 삭제 이력은 민감한 내용 없이 30일 보관한다. 백업을 운영하면 최대 7일을 적용하고 복원 시 삭제를 다시 반영한다.
