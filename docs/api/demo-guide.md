# 시연 패널(S-18) 사용 가이드

발표·점검용 시연 패널에서 쓰는 백엔드 API와 사용 순서를 정리한다. 계약 상세는 [OpenAPI](openapi.yaml)의 `Demo` 태그를 따른다. 기준 문서는 기능명세 DEMO-01~03과 [화면 동작 정책 §12](../spec/screen_policy.md)다.

## 핵심 규칙

- 시연 API는 `/api/v1/demo/**` 아래에 있으며 모든 요청에 `X-Demo-Key` 헤더가 필요하다.
- 서버에서 시연이 꺼져 있거나, 키가 없거나 틀리거나, 일반 게스트이거나, 세션이 없으면 모두 **404**다. 프런트는 404를 "시연 패널 없음"으로 처리하고 오류 화면을 띄우지 않는다.
- 시연 데이터는 **시연 게스트**(`guests.kind = 'DEMO'`) 단위로 분리된다. 타임머신·프리셋·초기화는 현재 시연 게스트의 데이터만 바꾸며, 일반 게스트의 기록은 바뀌지 않는다.
- 시연 게스트에게는 실제 Web Push(공개 알림·재알림)가 나가지 않는다.
- 프리셋 문구는 모두 `[시연 예시] `로 시작하며 AI를 호출하지 않는다. 위기 안내 프리셋은 없으므로 전화 연결 화면이 자동으로 열리지 않는다.

## 1. 서버 설정 (시연 담당자)

시연을 쓸 서버에서만 아래 두 값을 설정한다. 둘 중 하나라도 없으면 시연 API는 모두 404다.

```properties
# .env (저장소에 커밋하지 않는다)
NIGHTVAULT_DEMO_ENABLED=true
NIGHTVAULT_DEMO_KEY=<추측하기 어려운 임의 문자열>
```

- 키는 예를 들어 `openssl rand -base64 24`로 만든다.
- 키는 프런트 코드·빌드 환경변수·저장소에 넣지 않는다. 발표 담당자가 시연 패널에서 직접 입력한다.
- 운영 서버에서는 기본값(`false`)을 유지하고, 발표가 끝나면 다시 끈다.

## 2. 시크릿 창에서 시작하기

`POST /demo/session`은 브라우저의 게스트 쿠키를 **시연 게스트 쿠키로 덮어쓴다**. 평소 쓰던 금고를 이어서 쓰려면 반드시 **시크릿(비공개) 창**에서 시연한다. 시크릿 창을 닫으면 시연 쿠키도 사라진다. 서버의 시연 데이터는 일반 게스트와 같은 30일 보관 규칙을 따른다.

## 3. 프런트 연동

| 순서 | 호출 | 설명 |
| --- | --- | --- |
| 1 | `GET /csrf` | 쓰기 요청 전 CSRF 토큰을 받는다. |
| 2 | `POST /demo/session` + `X-Demo-Key` | 시연 게스트를 발급한다. 이미 시연 게스트면 그대로 유지한다. **응답 후 `GET /csrf`를 다시 호출한다.** |
| 3 | `GET /demo/status` + `X-Demo-Key` | 200이면 패널과 "시연 중" 배지를 보여준다. `lockedCount`, `publicCount`, `failedRequestCount`, `nextPublishAt`을 표시한다. |
| 4 | `POST /demo/presets` | 상태별 예시를 만든다. 다시 누르면 같은 구성으로 교체된다. |
| 5 | `POST /demo/time-machine` `{"preset":"TO_PUBLISH"}` | 가장 가까운 잠긴 걱정의 공개 시각으로 이동한다. 특정 걱정은 `worryId`를 함께 보낸다. |
| 6 | `POST /demo/time-machine` `{"preset":"PLUS_24H"}` | 24시간 이동한다. 열람한 공개 기록이 회고 후보가 된다. |
| 7 | `POST /demo/reset` | 시연 데이터만 지운다. 시연 게스트와 세션은 유지된다. |

- 쓰기 요청(2·4~7)에는 기존과 같이 `X-CSRF-TOKEN`도 보낸다.
- 타임머신·프리셋·초기화가 끝나면 응답의 `status`(또는 응답 본문)로 패널을 갱신한다. 홈·금고·기록 화면의 캐시는 무효화하고 다시 조회한다.
- 타임머신 오류: 잠긴 걱정이 없으면 `409 NO_LOCKED_WORRY`, 이미 공개된 걱정을 지정하면 `409 ALREADY_PUBLIC`이다. 버튼을 비활성화하거나 안내 문구로 처리한다.
- 시연 패널은 일반 내비게이션에 넣지 않는다. 예를 들어 `/demo` 경로로 직접 들어가게 한다.
- 시연 키는 메모리나 `sessionStorage`에만 두고, `localStorage`나 URL 쿼리에는 남기지 않는다.

## 4. 발표용 추천 순서

1. **프리셋**: 시크릿 창에서 `/demo`에 들어가 키를 입력하고 시연 시작(session)과 프리셋을 실행한다. 홈에서 잠긴 걱정 1개, 공개된 걱정 2개, 분석 실패 카드 1개를 보여준다.
2. **공개 이동**: 패널에서 "공개 시각으로 이동"(`TO_PUBLISH`)을 누른다. 잠겨 있던 발표 걱정이 공개되고, 금고에서 상세를 열어 요약과 추천 도움을 보여준다. 시연 게스트라 실제 푸시는 오지 않는다.
3. **활동**: 상세에서 추천 도움을 고른다. 액션은 세 단계를 체크해 완료하고, 공감은 바로 완료한 뒤 도움 평가를 저장한다. 휴식은 3분 타이머라 발표에서는 액션이나 공감을 권한다.
4. **24시간 이동**: 패널에서 "24시간 후로 이동"(`PLUS_24H`)을 누른다. 2에서 열람한 걱정도 공개 후 24시간이 지나 회고 대상이 된다.
5. **회고**: 상세 화면에서 회고 카드를 보여주고 응답한다. 후보는 공개 가능 시각이 가장 오래된 기록부터 나오므로, 프리셋의 지출 걱정이 먼저 나온다.
6. 발표를 다시 시작할 때는 **초기화** 후 **프리셋**을 다시 누른다. 프리셋만 눌러도 기존 시연 데이터는 교체된다.

## 5. 주의 사항

- **시연 게스트의 직접 제출과 실패 재시도에는 예시 분석을 사용한다.** 시연 게스트가 S-03에서 걱정을 제출하거나 실패한 분석을 재시도하면, 서버는 외부 AI 호출 없이 `[시연 예시]` 결과로 봉인한다. 입력한 원문·메모·공개 예정 시각은 그대로 저장된다. 일반 게스트의 제출과 재시도는 기존 분석 경로로 처리한다. [시연 분석 테스트 기록](../demo-analysis-test-record.md)
- 타임머신은 시연 게스트의 모든 시각을 함께 당기므로, 여러 번 이동하면 30일 보관 기간이 지나 기록이 만료될 수 있다. 이때는 프리셋을 다시 만든다.
- 진행 중인 휴식 타이머도 함께 당겨지므로, 타임머신 후에는 남은 시간이 0이 될 수 있다.
- 분석 실패 카드는 접수 후 24시간 동안만 홈에 보인다. `PLUS_24H` 이동 후에는 사라지는 것이 정상이다.
