# 발표 시연 시나리오 (초안)

5분 발표에서 보여줄 시연 순서, 사전 점검, 비상 계획을 정리한다. 화면 ID는 [화면 동작 정책 §12](spec/screen_policy.md#12-화면시연-기준), 시연 API는 [시연 패널 가이드](api/demo-guide.md), 점검 스크립트는 [개발용 스크립트](../scripts/dev/README.md)를 따른다.

> 프런트 화면 문구와 버튼 이름은 아직 확정되지 않았다. **FE 확인 필요**로 표시한 부분은 프런트 구현이 끝나면 실제 문구로 바꾼다. 화면 동작 정책에 문구가 정해진 경우에도 실제 구현과 다를 수 있어 같이 표시했다.

## 0. 시연 전제

- 발표용 휴대폰의 **시크릿(비공개) 창**에서 시연 게스트로 진행한다. 평소 쓰던 금고 쿠키를 덮어쓰지 않기 위해서다.
- 시연 게스트의 걱정 제출은 외부 AI를 호출하지 않고 `[시연 예시]` 결과로 봉인된다. 화면에 보이는 요약·추천·액션 단계는 예시 분석이다. 발표에서 "실제 AI 결과"라고 말하지 않는다.
- 발표 시작 시점의 금고는 프리셋 상태다: 잠긴 걱정 1개(발표 걱정, 내일 공개), 공개된 걱정 2개(미열람 1개, 회고 대상 1개), 분석 실패 카드 1개.
- 직접 입력하는 걱정은 기본 공개 시각(다음 오전 8시)을 그대로 둔다. 프리셋의 잠긴 걱정은 24시간 뒤 공개라서, 그래야 "공개 시각으로 이동"이 방금 맡긴 걱정을 연다.

## 1. 발표 시연 순서 (5분 기준)

시연 구간 합계 약 4분 40초, 여유 20초.

| # | 화면 | 누를 버튼 (FE 확인 필요) | 말할 핵심 한 줄 | 예상 시간 |
| --- | --- | --- | --- | --- |
| 1 | S-02 홈 | 없음 (화면만 보여줌) | "밤에 맡긴 걱정은 정해 둔 아침까지 잠겨 있어요." | 0:20 |
| 2 | S-03 걱정 입력 | 걱정 붙여넣기 → 불안도 4 → 내일 확인할 것(선택) → 다음 | "잠들기 전, 머릿속 걱정을 한 줄로 꺼내 놓습니다." | 0:35 |
| 3 | S-04 공개 시간 | 기본 시각 유지, 알림 꺼짐 유지 → 봉인하기 | "공개 시간은 기본 아침 8시, 그 전에는 원문도 볼 수 없어요." | 0:15 |
| 4 | S-05 → S-06 봉인 완료 | 홈으로 | "맡겨두었어요. 이제 폰을 내려놓아도 돼요." (정책 문구, FE 확인 필요) | 0:15 |
| 5 | S-18 시연 패널 | 공개 시각으로 이동 (`TO_PUBLISH`) | "시연을 위해 밤을 건너뛰어 아침으로 가 보겠습니다." | 0:20 |
| 6 | S-02 → S-07 → S-08 상세 | 금고 열기 → 방금 공개된 걱정 → 현재 불안도 2 선택 | "아침에 다시 보면, 어젯밤 걱정이 정리된 형태로 돌아와요." | 0:35 |
| 7 | S-08 요약 수정 | 요약 수정 → 한 단어 고치기 → 저장 | "정리가 내 마음과 다르면 직접 고칠 수 있어요." | 0:25 |
| 8 | S-08 → S-10 액션 | 10분 액션 → 3단계 체크 → 전체 완료 | "도움은 내가 고릅니다. 오늘은 10분 안에 할 수 있는 작은 행동이에요." | 0:35 |
| 9 | S-13 활동 완료 | 도움 됨 → 기록 보기 | "도움이 됐는지 남겨 두면 다음 추천의 근거가 돼요." | 0:15 |
| 10 | S-14 기록 | 방금 기록 선택 | "봉인 전 4에서 지금 2로, 불안도 변화를 기록으로 봅니다." | 0:20 |
| 11 | S-18 시연 패널 | 24시간 후로 이동 (`PLUS_24H`) | "하루가 지났다고 해 보겠습니다." | 0:15 |
| 12 | S-08 회고 카드 | 금고 → 걱정 상세 → 회고 카드 응답(괜찮아짐) | "하루 지난 걱정은 실제로 어떻게 됐는지 돌아보게 해요." | 0:30 |

- 2번 걱정 문구는 미리 메모 앱에 적어 두고 붙여넣는다. 예: "내일 팀 회의에서 내 의견을 말할 수 있을지 걱정돼요." 위기 표현이 없는 평범한 문장으로 정한다.
- 6번에서 현재 불안도를 고르지 않으면 10번의 전후 비교가 "4 → 미기록"으로 나온다.
- 12번 회고 카드는 공개 가능 시각이 가장 오래된 기록부터 나오므로 프리셋의 지출 걱정이 뜬다. 현재 보고 있는 걱정은 회고 후보에서 빠진다. 어느 상세 화면에서 보여줄지는 FE 확인 필요.
- 5번·11번은 S-18을 오가는 방식(별도 탭, 패널 버튼 위치)이 FE 확인 필요다.

### 도움 선택: 액션 또는 휴식

| 선택 | 진행 | 비고 |
| --- | --- | --- |
| **액션 (기본)** | S-10 3단계 체크 → 전체 완료 → S-13 | 30초 안팎으로 끝난다. 시연 예시 추천도 액션이다. |
| 휴식 | S-11 시작하기 → 타이머 몇 초 보여주기 → 그만두기 → S-08 | 기본 3분이라 끝까지 기다리지 않는다. 그만두면 S-13으로 가지 않으므로 9번(평가)을 건너뛰고 10번으로 간다. |

### S-16 위기 안내를 보여줄지 (선택지)

시연 게스트는 어떤 입력이든 `[시연 예시]` 성공으로 봉인하므로, 시연 창에서 `[mock:guidance]`를 입력해도 S-16이 나오지 않는다. `[mock:guidance]`는 **일반 게스트**가 **모의 분석기**(Spring 내부 가짜 분석기 또는 Python `mock` 모드)를 쓰는 서버에서만 S-16으로 간다. 배포 서버가 `solar` 모드면 이 입력은 일반 문장으로 처리된다.

| 선택지 | 방법 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 캡처·영상으로 설명 (권장)** | 발표 자료에 S-16 화면 캡처나 짧은 녹화를 넣고 15초 설명 | 시연 흐름과 요청 한도에 영향이 없다. | 라이브가 아니다. |
| B. 라이브 `[mock:guidance]` | 모의 분석기 서버에 일반 게스트(다른 시크릿 창)로 접속해 입력 | 실제 분기 화면을 보여준다. | 서버·창을 하나 더 준비해야 하고, 제출 한도를 쓴다. 배포 서버에서는 동작하지 않는다. |
| C. 생략 | 말로만 "위기 표현이 감지되면 별도 도움 안내로 연결된다"고 언급 | 시간을 아낀다. | 화면 근거가 없다. |

- 어느 선택지든 핵심 한 줄: "위기 표현이 보이면 봉인 대신 도움 안내로 연결하고, 전화는 사용자가 선택할 때만 겁니다."
- 시연에서 전화 연결을 자동 실행하지 않는다. B를 고르면 전화 버튼은 누르지 않는다.

## 2. 발표 전 체크리스트

### 전날

- [ ] 배포 서버 스모크 테스트를 시연 흐름 포함으로 돌려 `전체 통과`를 확인한다.
  ```powershell
  $key = Read-Host '시연 키'
  .\scripts\dev\smoke-test.ps1 -BaseUrl https://<배포 도메인> -DemoKey $key
  ```
- [ ] 배포 서버에 `NIGHTVAULT_DEMO_ENABLED=true`, `NIGHTVAULT_DEMO_KEY`가 설정돼 있는지 BE1과 확인한다.
- [ ] 위 1장 순서대로 처음부터 끝까지 리허설하고 시간을 잰다.
- [ ] 리허설을 휴대폰 화면 녹화로 남겨 **비상용 영상**을 만든다. 노트북과 USB에 둘 다 저장한다.
- [ ] S-16 캡처(선택지 A)를 발표 자료에 넣는다.
- [ ] 2번에 붙여넣을 걱정 문장을 메모 앱에 적어 둔다.
- [ ] FE 확인 필요 표시를 실제 버튼·문구로 바꾼다.

### 당일 아침 (발표 30분 전쯤)

- [ ] 스모크 테스트를 한 번 더 돌린다. 스모크 테스트도 게스트 생성·걱정 제출 한도를 쓰므로 **발표 직전 1분 안에는 돌리지 않는다.**
- [ ] 발표용 휴대폰에서 **시크릿 창**을 연다.
- [ ] `/demo`로 들어가 시연 키 입력 → 시연 시작 → 초기화 → 프리셋 순서로 실행한다. 키 입력은 **미러링을 켜기 전에** 한다.
- [ ] 시연 패널 상태가 잠긴 1, 공개 2, 실패 1인지 확인한다. 그 뒤로는 시연 창을 건드리지 않고 홈 화면에 둔다.
- [ ] 시크릿 창을 닫지 않는다. 닫으면 시연 쿠키가 사라진다.

### 휴대폰·미러링

- [ ] 미러링 방식(유선, AirPlay, scrcpy 등)을 발표장 화면에 실제로 연결해 본다.
- [ ] 자동 화면 잠금 끄기, 방해 금지 켜기, 밝기 최대, 충전 80% 이상.
- [ ] 다른 앱 알림·메신저 미리보기가 화면에 뜨지 않는지 확인한다.

### 와이파이

- [ ] 발표장 와이파이로 배포 서버 접속을 확인한다.
- [ ] 휴대폰 데이터·핫스팟을 바로 켤 수 있게 둔다(데이터 잔량 확인).
- [ ] 발표장 공용망은 여러 팀이 같은 IP를 쓸 수 있다. 걱정 제출은 IP당 분당 6건이라, 같은 망에서 다른 사람이 동시에 시연하면 429가 날 수 있다.

## 3. 비상 계획

| 상황 | 증상 | 대처 |
| --- | --- | --- |
| 서버 응답 없음 | 화면이 멈추거나 오류·재시도 화면 (FE 확인 필요) | 새로고침 1번. 그래도 안 되면 바로 **비상용 영상**으로 바꿔 같은 대사로 진행한다. |
| 분석 지연 | S-05에서 15초 넘게 대기 | "나가도 정리는 계속돼요"를 보여주고 홈으로 나간다. 이후 **프리셋의 잠긴 걱정**(발표 걱정)으로 5번부터 진행한다. |
| 429 요청량 제한 | "요청이 너무 많아요" 안내 (FE 확인 필요) | 다시 누르지 않는다. 2~4번 입력을 건너뛰고 **프리셋의 잠긴 걱정**으로 5번부터 진행한다. `Retry-After`는 10초다. |
| 와이파이 끊김 | 요청 실패, 로딩 지속 | **휴대폰 데이터·핫스팟**으로 전환한다. 시크릿 창을 닫지 않으면 쿠키와 시연 데이터는 그대로 이어진다. 30초 안에 복구되지 않으면 영상으로 바꾼다. |
| 실제 AI 오류 | 일반 게스트 분석 실패 | 시연 게스트는 AI를 호출하지 않아 본 시연에는 영향이 없다. 실제 AI를 따로 보여주려던 경우에만 해당하며, 그 부분은 생략하고 프리셋으로 설명한다. |
| 시연 패널 404 | 패널이 안 열림 | 키 재입력(미러링 끈 상태). 안 되면 서버 설정 문제이므로 영상으로 바꾼다. |
| 타임머신 `409 NO_LOCKED_WORRY` | 공개 이동 실패 | 잠긴 걱정이 없다는 뜻이다. 프리셋을 다시 누르고 5번부터 진행한다. |
| 시크릿 창을 닫음 | 첫 이용 안내 화면이 뜸 | 새 시크릿 창 → `/demo` → 시연 시작 → 프리셋(약 30초). 시간이 없으면 영상으로 바꾼다. |

## 4. 발표 중 하지 말 것

- **실패 카드 재시도 누르기** — 시연 게스트의 재시도는 예시 결과로 봉인돼 금고 구성이 바뀌고, 걱정 제출 한도(IP당 분당 6건)도 쓴다. 실패 카드는 "이런 상태도 보여준다"고 말로만 짚는다.
- **위기 문장 직접 입력** — 시연 게스트는 위기 분기를 타지 않아 위기 문장이 일반 걱정처럼 봉인되는 잘못된 장면이 나온다. 청중에게도 부담이다. S-16은 1장의 선택지로만 보여준다.
- **타임머신 여러 번 누르기** — 시연 게스트의 모든 시각이 함께 당겨진다. 여러 번 이동하면 30일 보관이 지나 기록이 만료되고, 휴식 타이머가 0이 되고, 실패 카드(접수 후 24시간)가 사라진다. `TO_PUBLISH` 1번, `PLUS_24H` 1번만 누른다.
- **발표 중 프리셋·초기화 누르기** — 방금 맡긴 걱정을 포함해 시연 데이터가 교체된다. 비상 계획에 적힌 경우에만 쓴다.
- **미러링 중 시연 키 입력** — 키가 화면에 노출된다.
- **휴식 타이머 3분 기다리기** — 몇 초만 보여주고 그만둔다.
