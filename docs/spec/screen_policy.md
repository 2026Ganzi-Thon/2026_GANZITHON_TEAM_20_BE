# 화면 동작 정책

> 출처: 노션 "화면 동작 정책" (2026-11-14 기준 복사본). 기획 변경 시 노션이 우선한다.

> **용도:** 기획·디자인·개발팀의 공통 화면 설계 기준
>
> 와이어프레임의 화면과 가이드를 기준으로 작성했습니다. 화면과 문서가 충돌하는 경우 이 문서의 수정 기준을 적용하고 와이어프레임도 함께 갱신합니다.
>
> 기능별 담당자·기한·진행 상태는 별도 기능명세서에서 관리합니다.

## 1. 서비스와 핵심 흐름

**잠들기 전 걱정을 짧게 맡기고, 공개 시간 이후 AI가 정리한 내용을 확인하며 필요한 도움을 직접 선택하는 모바일 웹 서비스입니다.**

### 최초 이용

S-01 첫 안내 → 게스트 생성 → S-03 걱정 입력

- 첫 이용에는 빈 홈을 필수로 거치지 않습니다.
- 기존 게스트의 재접속은 S-02 홈으로 연결합니다.

### 걱정 맡기기

홈 → 입력·불안도 → 공개 시간 → 분석·저장 → 봉인 완료

- 분석 중 이탈을 허용합니다.
- 화면 이탈은 서버 요청 취소를 의미하지 않습니다.
- 다른 화면을 보는 사용자를 봉인 완료로 강제 이동시키지 않습니다.

### 잠긴 걱정 관리

홈의 ‘잠긴 걱정 보기’ → S-07 목록 → 잠금 안내 → 공개 시간 변경 또는 삭제

### 공개 후 확인

홈의 ‘금고 열기’ → S-07 목록 → S-08 상세 → 도움 선택

| 도움 | 흐름 |
| --- | --- |
| 걱정 파쇄 | 삭제 확인 → 삭제·파쇄 완료 → 홈 또는 금고 |
| 10분 액션 | 단계별 실행 → 전체 완료 → S-13 |
| 짧은 휴식 | 직접 시작 → 타이머 → 완료 확인 → S-13 |
| 그냥 들어줘 | 공감 메시지 → 읽었어요 → S-13 |

파쇄는 S-13으로 이동하지 않으며 도움 여부를 묻지 않습니다.

## 2. 구현 범위

| 구분 | 포함 기능 |
| --- | --- |
| 이용 시작 | 게스트 생성·인증·접근 제한 안내 |
| 홈 | 금고 상태·분석 상태·활동 이어하기·재알림 |
| 밤 | 걱정 입력·불안도·선택 메모·공개 시간·분석·봉인 |
| 잠긴 걱정 | 잠금 안내·공개 시간 변경·공개 전 삭제 |
| 공개 후 | 상세·AI 정리 수정·도움 4종 |
| 기록 | 활동·평가·불안도 비교·회고·과거 경험 |
| 알림 | 공개 알림·선택형 재알림·권한·실패 안내 |
| 운영 | 위기 대응·삭제·자동 만료·시연·공통 오류 |

**선택 구현:** 호흡 가이드, OCR, 음성 입력, 감정 패턴 리포트, 취침 전 선택 알림, 이메일 대체 알림, 계정 연결

**제외:** 실시간 AI 채팅, 익명 커뮤니티, 코인·상점·꾸미기, 위치 추천, 걱정 외부 공유

호흡 가이드는 없어도 봉인 흐름이 정상 연결되어야 합니다.

| 휴식 시간 | 기본 3분 |

| 재알림 | 요청한 경우 30분·1시간 뒤 1회 |

### 시간과 입력

- 공개·예약·만료 판단은 서버 시각을 기준으로 합니다.
- 화면은 사용자 현지 시간대로 표시합니다.
- 날짜·요일은 실제 날짜에서 계산하며 예시 문구를 고정하지 않습니다.
- 글자 수 기준은 화면과 서버에서 통일합니다.
- 불안도는 기본 선택값 없이 숫자와 설명을 함께 표시합니다.
- 원문은 일반 텍스트로 처리하며 임의로 수정하지 않습니다.

## 4. 이용 시작·홈·공통 이동

### 4-1. 게스트 이용

- 로그인 없이 같은 브라우저에서 이용합니다.
- 서버 발급 인증 정보로 개인 금고를 구분합니다.
- 하드웨어 식별·브라우저 지문 수집을 이용하지 않습니다.
- 인증은 기본 30일 유지하며 유효한 접속 시 갱신합니다.
- 개별 걱정의 보관 기간은 인증 유지 기간과 별개입니다.
- 다른 기기·브라우저와 자동 동기화하지 않습니다.
- 공용 브라우저의 다른 이용자가 접근할 수 있음을 안내합니다.

**첫 이용 안내**

> 같은 브라우저에서 내 금고를 다시 열 수 있어요. 브라우저 데이터를 지우거나 다른 기기로 접속하면 기존 금고에 접근하거나 복구하기 어려울 수 있어요.

### 4-2. 인증 오류

- 인증 정보가 전혀 없으면 일반적으로 첫 이용 안내를 표시합니다.
- 기존 인증 정보가 있으나 서버에서 만료·무효로 확인되면 접근 오류 화면을 표시합니다.
- 브라우저 정보가 완전히 삭제된 사용자를 신규 사용자와 항상 구분할 수 있다고 가정하지 않습니다.
- ‘새로 시작하기’는 새 게스트 금고를 생성한 뒤 S-03으로 연결합니다.
- 서버에 남은 이전 기록은 별도의 만료·삭제 정책을 따릅니다.

### 4-3. 홈

| 상태 | 표시·행동 |
| --- | --- |
| 기록·요청 없음 | 빈 금고 안내, 걱정 맡기기 |
| 분석 중 | 정리 중 카드 → 해당 S-05 |
| 최종 실패 | 정리 실패 카드 → 상태 확인 후 재시도 또는 재입력 |
| 잠긴 기록 있음 | 잠긴 수·가장 가까운 공개 시각·잠긴 걱정 보기 |
| 공개 기록 있음 | 공개 가능한 수·금고 열기 |
| 활동 있음 | 최근 진행·일시정지 활동 이어하기 |
| 재알림 있음 | 예정 시각·취소 |

- 저장된 기록과 분석 중 요청은 별개로 표시합니다.
- 분석 중 요청을 잠긴 기록 수에 포함하지 않습니다.
- 상태 카드에 원문·메모·분석 결과를 표시하지 않습니다.
- 공개 시각이 서로 다르면 한 시각에 모두 공개되는 것처럼 표시하지 않습니다.
- 분석 실패 카드는 사용자가 확인하고 닫을 수 있습니다.
- 실패 카드 닫기는 다른 걱정을 삭제하지 않습니다.
- 홈에서 원문을 자동으로 펼치지 않습니다.
- 밤 홈에는 과거 걱정의 원문·요약을 노출하지 않습니다.

### 4-4. 이동

- 하단 내비게이션은 홈·기록·설정입니다.
- S-02·S-14 목록·S-15에서 표시합니다.
- 입력·분석·봉인·도움 실행 중에는 숨깁니다.
- S-03 뒤로가기는 현재 상태의 홈으로 연결합니다.
- 기록이 있는 사용자를 빈 홈 상태로 초기화하지 않습니다.
- S-04 뒤로가기는 입력을 유지하며 S-03으로 연결합니다.
- 목록·상세의 뒤로가기는 들어온 화면으로 연결합니다.
- 직접 링크 등 이전 화면이 없으면 홈 또는 해당 목록으로 연결합니다.

## 5. 밤 — 입력·분석·봉인

### 5-1. 입력

한 화면에 걱정·불안도·선택 메모를 배치합니다.

| 항목 | 필수 | 정책 |
| --- | --- | --- |
| 걱정 | 예 | 최대 500자·글자 수 |
| 불안도 | 예 | 1~5·기본값 없음 |
| 내일 확인할 것 | 아니요 | 최대 100자 |

불안도 문구는 와프 기준으로 **거의 없음 / 조금 / 보통 / 많이 / 아주 많이**를 사용합니다.

- 필수 입력이 유효하면 다음 버튼을 활성화합니다.
- 다음 선택만으로 서버 기록을 만들지 않습니다.
- 제출 전 앞뒤 이동 시 초안을 유지합니다.
- 미저장 이탈 시 유실 가능성을 안내합니다.
- 영구 저장소에 원문을 자동 저장하지 않습니다.
- 새로고침·종료 후 초안 복구는 보장하지 않습니다.

### 5-2. 공개 시간

- 날짜·시각을 함께 표시합니다.
- 미래이며 삭제 예정 시각 이전인 값만 허용합니다.
- 제출 시 서버에서 재검사합니다.
- 개별 변경은 기본 설정을 바꾸지 않습니다.
- 사용자 기본값을 변경한 경우 다음 등록부터 그 시각을 사용합니다.
- 첫 알림 제안은 이 화면에서 한 번만 제공합니다.
- 알림 선택 기본값은 꺼짐입니다.
- 권한 거절·미지원이어도 봉인할 수 있습니다.

### 5-3. 분석 진행과 이탈

입력 검증 → 위기 대응 확인 → AI 생성·검증 → 저장

- 요청 식별자로 서버 처리 상태를 추적합니다.
- 중복 제출·재시도로 같은 걱정을 중복 생성하지 않습니다.
- 접수된 요청은 화면을 나가도 처리합니다.
- S-05 닫기·뒤로가기는 홈 이동입니다.
- 제출 전 입력 화면으로 돌아가 같은 요청을 수정하지 않습니다.
- 사용자는 별개의 새 걱정을 작성할 수 있습니다.
- 접수 확인 전에는 ‘나가도 계속된다’고 확정 안내하지 않습니다.

**접수 후 안내**

> 나가도 정리는 계속돼요. 처리 결과는 홈에서 확인할 수 있어요.

| 상태 | 화면 |
| --- | --- |
| 진행 중 | 처리 안내·닫기 |
| 15초 초과 | 지연 안내 |
| 30초 초과·결과 미확인 | 상태 확인·홈 이동 |
| 서버 최종 실패 | 재시도 |
| 저장 성공 | 현재 화면에 맞게 완료 반영 |

**30초 경과만으로 실패를 선언하지 않습니다.**

서버는 최종 성공·실패를 반환해야 하며 무기한 처리 중으로 남기지 않습니다. 처리 제한 시간·자동 재시도 횟수는 개발 설계에서 정합니다.

### 5-4. 성공·실패 반영

| 현재 위치 | 저장 성공 시 |
| --- | --- |
| 해당 S-05 | S-06 이동 |
| 홈 | 처리 카드 제거·금고 갱신·성공 안내 |
| 다른 화면·다른 요청 | 현재 화면 유지 |
| 브라우저 종료 | 다음 접속 시 금고 상태 반영 |

- 화면 밖 완료에 봉인 연출을 강제 재생하지 않습니다.
- 이미 성공한 요청을 다시 열면 재저장 없이 완료 상태로 안내합니다.
- 저장 시 공개 시각이 지났으면 공개 가능 상태입니다.
- 원문은 자동으로 열지 않습니다.

**실패 시**

- 재시도 전 기존 요청 상태를 확인합니다.
- 성공 상태면 재분석하지 않습니다.
- 진행 중이면 상태만 표시합니다.
- 최종 실패하고 입력이 남아 있으면 재시도합니다.
- 재처리할 입력이 없으면 재입력을 안내합니다.
- 공개 시각이 지났으면 재제출 전 다시 선택합니다.
- 실패 요청을 일반 기록·회고·추천에 포함하지 않습니다.

### 5-5. 봉인 완료

- 서버 저장 성공 후에만 표시합니다.
- 기본 문구: **“맡겨두었어요. 이제 폰을 내려놓아도 돼요.”**
- 공개 예정 일시를 표시합니다.
- 홈으로·새 걱정 맡기기·재알림 보조 버튼을 제공합니다.
- 공개 알림을 다시 묻지 않습니다.
- 자동 팝업 없이 그대로 종료할 수 있습니다.
- 이미 공개 시각이 지났다면 ‘지금 확인할 수 있어요’로 표시합니다.

### 5-6. 재알림

- 버튼: **“조금 뒤에 다시 알려주세요”**
- 작은 회색 보조 버튼이며 충분한 대비·터치 영역을 확보합니다.
- 30분 뒤·1시간 뒤·예약하지 않기를 제공합니다.
- 선택 전 예약 버튼은 비활성화합니다.
- 예약 성공 시각을 기준으로 계산하고 실제 예정 시각을 표시합니다.
- 사용자당 활성 예약은 1개입니다.
- 기존 예약이 있으면 교체 안내 후 변경합니다.
- 권한·예약 실패 시 기존 예약을 잃지 않도록 처리합니다.
- 공개 알림 동의와 별개입니다.
- 화면 밖에서 봉인이 완료되어도 자동 예약하지 않습니다.
- 성공 후 같은 시트에서 예정 시각·닫기·취소를 제공합니다.

## 6. 금고 목록·잠금 안내·상세

### 6-1. S-07 금고 목록

| 구분 | 표시 | 선택 시 |
| --- | --- | --- |
| 공개 | 작성 일시·요약 한 줄·봉인 전 불안도·미확인 표시 | S-08 |
| 잠김 | 작성 일시·공개 예정 일시 | 잠금 안내 |

- 영역별 작성 시각 최신순입니다.
- 요약은 한 줄 말줄임하며 수정본을 우선 사용합니다.
- 목록 요약 노출은 상세 확인으로 처리하지 않습니다.
- ‘새로 공개’ 표시는 최초 상세 확인 전까지만 제공합니다.
- 분석 중·실패·삭제·만료는 목록에서 제외합니다.

### 6-2. 잠금 안내

S-07의 바텀시트로 구성합니다.

- 작성·공개 일시만 표시합니다.
- 원문·메모·요약·불안도는 숨깁니다.
- 공개 시간 변경·삭제·닫기를 제공합니다.
- 조기 열기 버튼은 없습니다.
- 변경은 미래이며 삭제 예정 시각 이전만 허용합니다.
- 변경 성공 시 홈·목록·잠금 안내·공개 알림을 갱신합니다.
- 공개된 뒤 다시 잠그지 않습니다.
- 변경 취소·삭제 취소는 잠금 안내로 복귀합니다.
- 공개 전 삭제는 연출 없이 목록 복귀입니다.
- 열린 중 공개 시각 도달 시 서버 확인 후 ‘걱정 확인하기’를 제공합니다.
- 시간 변경은 숨기고 삭제·닫기는 유지합니다.
- 원문은 자동으로 펼치지 않습니다.

### 6-3. S-08 상세

와프 순서에 맞춰 다음을 배치합니다.

1. 조건에 맞는 지난 걱정 회고 카드
2. 원문·봉인 전 불안도·선택 메모
3. AI 정리·수정
4. 현재 불안도·건너뛰기
5. 관련 과거 경험 카드
6. 도움 4종

- 회고·과거 경험은 대상이 없으면 숨깁니다.
- S-08 실제 진입 시 최초 상세 확인을 기록합니다.
- S-14 상세를 먼저 열었다면 그 열람도 최초 상세 확인으로 기록합니다.
- 단순 목록 조회는 열람 완료가 아닙니다.
- 현재 불안도는 선택이며 수정은 덮어쓰기입니다.
- 도움은 모두 제공하고 AI 추천 하나만 강조합니다.

### 6-4. AI 정리 수정

- 원문은 읽기 전용입니다.
- 요약만 최소 1자~최대 500자로 수정합니다.
- 저장·취소 시 S-08로 복귀합니다.
- 수정본은 S-07·S-08·S-14 표시에 우선 적용합니다.
- 도움 추천·액션·휴식·공감은 자동 재생성하지 않습니다.
- 실패 시 초안을 유지하고 재시도합니다.

### 6-5. 도움 변경

- 같은 걱정에 진행 중·일시정지 활동이 있을 때 다른 도움을 고르면 확인창을 제공합니다.
- 취소하면 기존 상태 유지입니다.
- 확인하면 기존 활동을 중단하고 새 도움으로 이동합니다.
- 액션 체크는 유지합니다.
- 휴식은 명시적 중단으로 처리하며 다시 시작하면 3분입니다.
- 과거 활동 이력은 유지합니다.
- 파쇄 선택은 변경 확인 후 별도의 삭제 확인을 거칩니다.

## 7. 도움 실행·완료

### 7-1. 파쇄

- 삭제 범위·복구 불가를 먼저 안내합니다.
- 확인 후 공통 삭제 처리를 수행합니다.
- 성공 전 완료를 표시하지 않습니다.
- 연출은 생략 가능하며 일반 버튼을 제공합니다.
- 소리는 기본 꺼짐입니다.
- 완료 후 홈으로·금고로를 제공합니다.
- S-13·도움 평가를 제공하지 않습니다.
- 기록 상세의 일반 삭제와 잠긴 기록 삭제는 같은 범위를 삭제하되 연출 없이 목록으로 돌아갑니다.

### 7-2. 10분 액션

- 3단계를 보여주며 별도 시작 버튼 없이 화면 진입 시 활동 시작을 기록합니다.
- 같은 활동을 재조회하면 시작 시각을 새로 만들지 않습니다.
- 체크 순서는 자유이며 완료 취소가 가능합니다.
- 세 단계 모두 체크하기 전 전체 완료 버튼은 비활성화합니다.
- 전체 완료 선택·저장 성공 후 S-13으로 이동합니다.
- ‘나중에 이어하기’는 중단 저장 후 S-08로 복귀합니다.
- 체크는 유지하며 기록에서 재개할 수 있습니다.
- 중단을 실패로 표현하지 않습니다.

### 7-3. 짧은 휴식

- 시작 전 안내·3분·시작하기·다음에 할게요를 제공합니다.
- 다음에 할게요는 시작 없이 S-08로 복귀합니다.
- 직접 시작한 뒤에만 타이머가 흐릅니다.
- 실행 중 화면 이탈은 중단이 아니며 시간은 계속 흐릅니다.
- 일시정지는 남은 시간을 유지합니다.
- 재개 시 종료 예정 시각을 다시 계산합니다.
- 0초가 되면 시간 종료 안내와 완료 버튼을 제공합니다. (원문은 "초가 되면"으로 표기)
- 시간 종료만으로 완료 처리하지 않습니다.
- 완료를 누르면 S-13으로 이동합니다.

**그만두기**

- 확인창을 열어도 현재 실행·정지 상태를 유지합니다.
- 계속하기는 기존 타이머로 복귀합니다.
- 그만두기는 중단 저장 후 S-08로 복귀합니다.
- 남은 시간은 재개용으로 유지하지 않고, 다시 시작하면 새 3분 활동입니다.
- S-13으로 이동하지 않습니다.
- 확인창의 남은 시간은 실행 중이면 갱신합니다.
- 확인창에서 시간이 끝나면 종료 상태를 반영하고, 취소 시 종료 화면으로 돌아갑니다.

### 7-4. 공감 메시지

- 봉인 시 생성한 메시지를 사용합니다.
- 실시간 입력창·추가 대화는 없습니다.
- 화면을 연 것만으로 완료 처리하지 않습니다.
- ‘읽었어요’ 선택·저장 성공 후 S-13으로 이동합니다.
- 확인되지 않은 사실이나 해결 결과를 단정하지 않습니다.

### 7-5. S-13 활동 완료

- 액션·휴식·공감에만 적용합니다.
- 활동 종류에 맞는 완료 문구를 표시합니다.
- 도움 됨·잘 모르겠음·도움 안 됨은 선택 입력이며 기본값은 없습니다.
- 평가 없이 홈·다음 걱정으로 이동해도 완료를 유지합니다.
- 평가 저장 실패는 활동 완료와 구분합니다.
- 불안도는 S-08 입력값을 사용하며 S-13에서 새로 받은 것처럼 처리하지 않습니다.
- 다음 걱정 보기는 공개된 다른 미확인 걱정이 있을 때 표시하고 S-07로 연결합니다.
- 대상이 없으면 해당 버튼을 숨깁니다.

## 8. 기록·회고·과거 경험

### 8-1. 기록 목록·상세

- 공개된 미삭제·미만료 기록을 작성 시각 최신순으로 표시합니다.
- 잠긴 기록·분석 중·실패 요청은 제외합니다.
- 목록은 작성 일시·요약·전후 불안도·최신 선택 도움을 표시합니다.
- 도움 미선택은 ‘아직 선택하지 않음’으로 표시합니다.
- 공개 후 불안도가 없으면 ‘4 → 미기록’처럼 표시할 수 있으나 변화량은 계산하지 않습니다.
- 상세에서는 전후 값이 모두 있을 때만 비교합니다.
- 원문·메모·AI 정리·활동·회고·평가를 제공합니다.
- 활동이 여러 개면 상세에 이력을 구분합니다.
- 기록 없음 화면에는 안내와 걱정 맡기기를 제공합니다.
- 삭제는 확인 후 연출 없이 목록으로 복귀합니다.

### 8-2. 회고

다음을 모두 만족한 기록을 최대 1개 제시합니다.

- 최초 공개 가능 시각으로부터 24시간 경과
- 상세 열람 완료
- 회고 미응답
- 미삭제·미만료
- 현재 확인 중인 걱정이 아님

- 최초 공개 가능 시각은 저장 성공과 공개 시각 조건이 모두 충족된 시점입니다.
- 예정 공개 시각 이후 저장되었다면 저장 성공 시점부터 계산합니다.
- 가장 오래된 최초 공개 가능 시각을 우선합니다.
- 괜찮아짐·진행 중·걱정대로 됨을 제공합니다.
- 오늘은 건너뛰기를 누르면 같은 현지 날짜에 다른 회고도 추가 제안하지 않습니다.
- 다음 날 이후 다시 후보가 될 수 있습니다.
- 응답 후 카드에는 완료 상태를 표시하고 반복 응답을 요구하지 않습니다.

### 8-3. 과거 경험

- 같은 사용자의 공개·미삭제·미만료 기록에서 관련 경험 최대 1개를 제공합니다.
- 현재·잠긴·분석 중·실패 기록은 제외합니다.
- 관련성이 충분하지 않으면 숨깁니다.
- 도움 됨 응답이 있을 때만 도움이 되었던 경험으로 표현합니다.
- 카드 선택은 해당 S-14 기록 상세로 연결합니다.
- 과거 방식의 현재 효과를 보장하지 않습니다.

## 9. 알림

### 9-1. 공개 알림

- 첫 등록 S-04에서 한 번 제안하고 이후 설정에서 변경합니다.
- 동의·권한·구독 성공을 구분합니다.
- 기본 꺼짐입니다.
- 같은 공개 시각의 기록은 하나로 묶습니다.
- 발송 직전 삭제·동의·구독·열람·중복 여부를 확인합니다.
- 개수는 발송 대상의 실제 개수로 표시합니다.
- 시각 변경·삭제·해제에 따라 예약을 갱신합니다.
- 설정에서 다시 켜면 미공개 기록부터 적용하며 과거 알림은 소급 발송하지 않습니다.
- 분석이 늦게 성공해 공개 시각이 지난 경우에는, 제출 당시 동의가 있고 아직 미확인이면 공개 가능 알림을 1회 발송 대상으로 등록합니다.
- 별도의 분석 완료 알림은 추가하지 않습니다.

**문구**

- 제목: 금고가 열렸어요
- 1개: 맡겨둔 걱정을 확인할 수 있어요
- 여러 개: 맡겨둔 걱정 N개를 확인할 수 있어요

선택 시 인증·상태 확인 후 S-07로 이동합니다.

### 9-2. 재알림

- 직접 예약한 경우에만 1회 발송합니다.
- 자동 반복·미확인 재촉은 없습니다.
- 연관 걱정 삭제 시 취소합니다.
- 공개 알림과 정확히 같은 시각이면 공개 알림 하나만 발송하고 재알림도 처리 완료로 정리합니다.
- 선택 시 S-02로 이동합니다.
- 걱정을 자동으로 열지 않습니다.

**문구**

- 제목: 말씀하신 시간이 됐어요
- 본문: 가능할 때 잠시 쉬어가세요. 앱을 다시 열지 않아도 괜찮아요.

금고가 이미 공개되거나 변경될 수 있으므로 ‘아직 잠겨 있어요’를 고정 문구로 사용하지 않습니다.

### 9-3. 오류

| 구분 | 처리 |
| --- | --- |
| 권한 거절 | 설정에서 변경 가능함을 안내, 권한창 반복 요청 없음 |
| 미지원 환경 | 권한 요청 시도 없이 지원 제한 안내 |
| 구독 실패 | 알림 활성화 실패 안내·재시도 |
| 예약 실패 | 예약 저장 실패 안내·재시도 |
| 알림 없이 계속 | 원래 화면으로 복귀, 걱정 제출을 자동 실행하지 않음 |

- 예약 실패가 이미 성공한 구독·동의를 임의로 꺼짐으로 바꾸지는 않습니다.
- 실제 상태를 구분해 안내합니다.
- 브라우저·기기에 따라 지원 조건이 다를 수 있으므로 ‘다른 브라우저면 반드시 된다’고 안내하지 않습니다.
- 알림에 원문·메모·요약·불안도·인증 정보를 포함하지 않습니다.
- 잠금화면 알림은 운영체제가 표시하는 예시이며 앱 내부 화면으로 구현하지 않습니다.
- 전송 요청 성공과 실제 도착·열람을 구분합니다.

## 10. 위기 대응

- 기존 별도 위기 대응 정책의 단일 S-16을 사용합니다.
- 현재의 명확한 위험 표현은 규칙과 맥락을 확인해 분기합니다.
- 규칙에서 명확한 신호가 확인되면 LLM 실패에도 안내를 제공합니다.
- 판단 전체 실패는 정상 분석으로 간주하지 않습니다.
- 불안도나 특정 단어 하나만으로 진단하지 않습니다.
- 안내는 공감 문구·도움 연결·서비스 역할 설명·홈으로로 구성합니다.
- 전화는 사용자가 선택할 때만 연결합니다.
- 전화 미지원 환경에는 번호 표시·복사를 제공합니다.
- 자동 신고·위치 전송·통화 성공 판정을 하지 않습니다.
- 봉인·파쇄·액션·휴식·공개 알림·재알림·평가를 제공하지 않습니다.
- 일반 기록·회고·추천에 편입하지 않습니다.
- S-05 이탈 후 앱 안에서 결과를 받으면 도움 안내 진입을 제공합니다.
- 브라우저 종료 후 위기 알림을 보내거나 재접속 시 위기 입력을 복원하지 않습니다.
- 원문·생성 결과의 임시 데이터는 삭제 대상으로 처리합니다.
- 해당 도움 안내는 진단이나 안전 확보를 보장하지 않습니다.

- 만료 즉시 조회·추천을 차단하고 삭제 작업을 수행합니다.
- 원문·메모·AI 결과·수정본·불안도·활동·회고·평가·검색·캐시·연결 예약을 삭제합니다.
- 삭제 시작 후 접근을 차단하고 부분 실패는 재처리합니다.
- 삭제 성공 전 완료를 표시하지 않습니다.
- 전체 삭제는 분석 중 요청도 중단·결과 폐기 대상으로 처리합니다.
- 늦게 도착한 AI 결과가 기록을 재생성하지 않도록 합니다.
- 서버 삭제 성공 후 브라우저 인증을 제거하고 S-01로 이동합니다.
- 실패 요청의 입력은 처리·재시도에 필요한 범위에서만 사용하고 최종 실패 후 서버 임시 원문은 삭제합니다.
- 브라우저 초안이 없으면 실패 재시도 시 재입력을 요구할 수 있습니다.
- 내용 없는 실패 상태는 접수 후 최대 24시간 표시하고 이후 정리합니다.

### 개인정보

- 인증·소유권을 모든 API에서 검사합니다.
- 민감한 원문·파생 정보는 암호화해 저장합니다.
- 원문·AI 응답·인증 정보를 일반 로그에 남기지 않습니다.
- 삭제 이력은 내용 없이 30일 보관합니다.
- 백업 운영 시 최대 7일 보관하고 복원 시 삭제를 재적용합니다.
- 외부 AI 보관 범위는 실제 제공자 조건에 맞춰 안내합니다.

### 공통 오류·표현

- 로딩·빈 상태·오류·재시도를 구분합니다.
- 결과 불명확을 성공으로 표시하지 않습니다.
- S-05 30초 대기는 일반 조회 오류와 구분합니다.
- 재접속·복귀 시 서버 상태를 조회합니다.
- 상태를 색상·소리·연출에만 의존하지 않습니다.
- 중요한 행동은 일반 버튼으로 제공합니다.
- 터치 영역은 모바일 웹 기준 최소 44×44 CSS px를 설계 목표로 합니다.
