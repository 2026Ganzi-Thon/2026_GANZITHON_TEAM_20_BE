## 2. 공통 상태 (기능명세서)

### 활동 상태

| 상태 | 의미 |
| --- | --- |
| 시작 전 | 아직 실행하지 않음 |
| 진행 중 | 실행 중 |
| 일시정지 | 휴식 정지 |
| 중단 | 나중에 하기·명시적 중단·도움 변경 |
| 완료 | 사용자 완료 확인·저장 성공 |

화면 이탈은 휴식 중단이 아니다. 중단과 완료를 구분한다.

### 요청·걱정 상태

접수 확인 중 / 분석 중 / 최종 실패 / 봉인됨 / 공개 가능 / 확인함 / 삭제 중 / 삭제됨 / 만료됨

### 기능 완료 처리 기준

- 정상 동작뿐 아니라 해당 행의 예외를 확인한다.
- 화면·API·데이터 연결을 확인한다.
- 다른 사용자의 기록에 접근할 수 없는지 확인한다.
- 삭제·만료된 기록을 다시 표시하지 않는지 확인한다.
- 공동 담당 기능은 주담당이 연동 결과를 확인한 뒤 완료로 변경한다.

## 3. BE2 설계에 바로 영향을 주는 점

1. **기록(S-14) 목록·상세는 BE2**, 금고(S-07·S-08) 목록·상세·열람(M-01, M-02)은 BE1. 최초 열람 저장과 접근 검사는 공유한다.
2. **worries 테이블 확장 필요 (BE1 합의)**: 요약 수정본(암호화), 수정 여부 플래그, 공개 후 불안도(anxiety_after).
3. **활동 테이블에 필요한 정보**: 걱정 ID, 도움 유형, 상태, 시작·종료 시각, 액션 체크 3개, 휴식 남은 시간(일시정지 시점 기준), 마지막 상태 변경 시각.
4. **평가는 활동과 별도 테이블**, 선택 입력, 기본값 없음.
5. **회고 건너뛰기**는 게스트별 현지 날짜·시간대를 저장한다.
6. **시연**은 별도 권한(ROLE)과 시연 데이터 구분 컬럼이 필요하다.

## 3-1. 화면 동작 정책에서 추가로 확인된 규칙

> 출처: 노션 "화면 동작 정책" (2026-11-14 기준). 기능명세서보다 구체적인 값만 옮겼다.

### 값 목록 (enum 후보)

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 도움 유형 | 파쇄 / 10분 액션 / 짧은 휴식 / 그냥 들어줘(공감) | §1 (OpenAPI `HelpType`: SHRED, ACTION, REST, EMPATHY) |
| 활동 평가 | 도움 됨 / 잘 모르겠음 / 도움 안 됨, 기본값 없음 | §7-5 |

### 액션 (§7-2)

- 화면 진입 시 활동 시작 기록. 같은 활동 재조회 시 시작 시각을 새로 만들지 않음
- 체크 순서 자유, **체크 취소 가능**
- 3단계 모두 체크 전 완료 불가
- "나중에 이어하기"는 중단 저장 후 S-08. 체크 유지, 기록에서 재개

### 휴식 (§7-3)

- 시작 전 화면: 안내·3분·시작하기·다음에 할게요. 다음에 할게요는 활동을 만들지 않음
- 직접 시작한 뒤에만 타이머가 흐름
- 일시정지는 남은 시간 유지, **재개 시 종료 예정 시각을 다시 계산** → `ends_at`(실행 중), `remaining_seconds`(정지 중) 저장 방식이 자연스러움
- 0초가 되면 종료 안내 + 완료 버튼, 시간 종료만으로 완료 아님
- 그만두기 확인창을 열어도 현재 실행·정지 상태 유지(서버 상태 변경 없음). 그만두기 확정 시 중단, 남은 시간은 버리고 다음엔 새 3분 활동
- 확인창이 열린 동안 시간이 끝나면 종료 상태 반영

### 공감 (§7-4)

- 봉인 시 생성한 메시지 사용(재생성 없음)
- 화면 열람만으로 완료 아님, "읽었어요" + 저장 성공 후 S-13

### 활동 완료 S-13 (§7-5)

- 액션·휴식·공감에만 적용 (파쇄 제외)
- 평가 없이 이동해도 완료 유지, 평가 저장 실패와 완료는 별개
- S-13에서 불안도를 새로 받지 않음 (S-08 값 사용)
- "다음 걱정 보기"는 공개된 다른 **미확인** 걱정이 있을 때만, S-07로 연결

### 기록 S-14 (§8-1)

- 공개·미삭제·미만료만, 작성 시각 최신순
- 목록: 작성 일시 · 요약(수정본 우선) · 전후 불안도 · 최신 선택 도움
- 도움 미선택은 "아직 선택하지 않음", 공개 후 불안도 없으면 "4 → 미기록"(변화량 계산 안 함)
- 상세: 원문·메모·AI 정리·활동 이력·회고·평가
- S-14 상세를 먼저 열어도 최초 상세 확인으로 기록 (§6-3, 금고 상세와 공통)

### 회고 (§8-2)

- 최초 공개 가능 시각 = 저장 성공과 공개 시각 조건이 모두 충족된 시점 = `max(sealed_at, publish_at)`
- 후보 조건: 최초 공개 가능 시각 + 24시간 경과 · 상세 열람 완료 · 회고 미응답 · 미삭제·미만료 · 현재 확인 중인 걱정 아님
- 가장 오래된 최초 공개 가능 시각 우선, 최대 1개
- 오늘은 건너뛰기: 같은 현지 날짜엔 다른 회고도 제안하지 않음, 다음 날 재후보

### 과거 경험 (§8-3)

- 같은 사용자의 공개·미삭제·미만료 기록 중 최대 1개
- 현재·잠김·분석 중·실패 제외, 관련성 부족하면 숨김
- "도움 됨" 평가가 있을 때만 도움이 되었던 경험으로 표현
- 선택 시 해당 S-14 상세로 이동

### 삭제·만료 (§11)

- 삭제 대상: 원문·메모·AI 결과·수정본·불안도·활동·회고·평가·검색·캐시·연결 예약
- 만료는 서버 제출 접수 시각 + 30일, 재시도·수정·열람으로 연장 없음
- 만료 즉시 조회·추천 차단 후 삭제 작업
- 전체 삭제는 서버 삭제 성공 후 브라우저 인증 제거, S-01 이동
- 잠긴 기록 삭제·기록 상세 삭제·파쇄는 같은 범위를 삭제 (§7-1)
